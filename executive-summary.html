Executive summary: making a GEMS submission

Current project status: not ready — no submission file

Do not upload a TIFF from this repository. This checkout contains no authorized competition data or validated candidate TIFF. There is deliberately no active download button. The input data page requires competition login; no authentication or data files were provided here.

A TIFF becomes eligible for the download button only after the shared writer produces it and the exact file passes all checks below and the preregistered holdout gate.

What the contest requires

DrivenData requests one GeoTIFF containing predictions for faults across the region. Per the official submission format, it must have:

  • the training data's projected CRS, EPSG:32611 (UTM zone 11N);
  • the same 100 m resolution, bounds, shape, and geotransform as the training data;
  • a single band of 32-bit float values, expressing confidence/probability in the range [0, 1];
  • data outside the study bounds represented as null/NaN (per the official format page).

The portal error “Predicted values must be in range [0, 1]” means the written output must be inspected for out-of-range values and nodata/sentinel handling. Check the output bytes after writing, not just the in-memory array. NaNs are only appropriate outside the footprint when accepted by the official format; the footprint must have no NaN. Do not replace nodata with an arbitrary large negative value.

Safe path to submission

  1. Obtain the official competition data through your authorized DrivenData account and place it in the project's documented data location. Do not copy a previous team's submission as a prediction.
  2. Use the shared cached feature stack, holdout evaluator, and submission writer. For this project, the preregistered holdout must hide whole fault segments with a buffer, derive catalogue-based features only from visible faults, mask visible faults pixel-exactly, and evaluate pooled DTI with α=0.2, β=0.8, and a 300 m triangular kernel.
  3. Before candidate placement, pass the lane duplicate checks against available registry rasters: rank correlation must not exceed 0.90, and no more than 70% of dots may fall within 3 px of one registry raster. Repeat these checks on final dots. Test each feature alone; AUC > 0.90 is a leakage canary.
  4. Promote for packaging only if the candidate beats the current holdout best under the preregistered rule. Include evaluator version, withheld-positive count, 95% CI, per-fold outcomes and the negative-control results.
  5. Re-open the exact GeoTIFF from disk and validate band count, dtype, all in-footprint values in [0,1], no NaNs inside the footprint, outside-footprint nodata, CRS, shape and affine transform. Record SHA-256 and the validation report.
  6. Only then show an explicit “Download validated submission TIFF” link and display a unique submission name and a note no longer than 140 characters. The user may download it, then use the official form to select the file, enter the name/note if requested, review competition rules and submit while signed in.
  7. Label an online score as ORGANIZER-CONFIRMED only when copied from the actual submission receipt or official scoring record. Holdout-DTI and modeled projections are not organizer scores.

The full details, hypothesis ranking, sourced findings, and current blockers are in the project README. Competition submission policy, slot caps, and the active form should be checked directly on DrivenData before submission.

Why this site currently has no download link

Review of this checkout found only a README and no raster data, submission sample, registry inventory, evaluator, writer, validator, or output. Guessing dimensions/transform or downloading a sibling TIFF would not meet the required validation and would violate the non-copying/duplicate checks. A fictitious GeoTIFF could be rejected or consume a scarce slot. The correct result is blocked, not-ready status until authorized inputs and shared tools are available.
