## Mission and operating brief

Build an auditable, scientifically grounded workflow for discovering previously unmapped geothermal-indicative faults for the [DOE GEMS Prize Challenge (#306)](https://www.drivendata.org/competitions/306/competition-doe-gems/). The useful outcome is a validated one-band GeoTIFF that can be downloaded and submitted, together with a unique name and a short note. A file is submission-ready only after it passes the official format checks and the preregistered spatial holdout; a modeled projection, local mirror score, or sibling-repository result is never an organizer score.

This repository is intended to become a continuously maintainable research-and-submission project: keep evidence and source links auditable, automate checks and reporting, make the submission state obvious at first visit, prevent invalid [0, 1] values, and treat every experiment (including negative results) as evidence. Keep Arena's Core Values central: **Maximize P(Win)** by not spending a scarce slot on an unvalidated idea, and **Own the Outcome** by reporting defects and limitations rather than hiding them.

### Mandatory experiment and release rules

1. **One method lane at a time.** Before running an experiment, define the single method/lane, compare it with available registry rasters, and stop/record a duplicate if rank correlation exceeds 0.90 or over 70% of candidate dots lie within 3 px of a registry raster's dots. Check the surface before placement and the final dots. The supplied request did not identify an unambiguous lane paragraph, and this checkout has no registry rasters, so no lane is selected here.
2. **Reuse shared tools; do not fork or rebuild them.** The intended workflow uses the template's cached feature stack, `evaluate_holdout.py`, and `submission_writer.py`. Holdout must hide whole fault segments with a buffer, derive catalogue-based features only from visible faults, mask visible faults pixel-exactly, and score pooled DTI (alpha 0.2, beta 0.8, 300 m triangular kernel). If a shared tool is defective, fix it once in the template and report the change. None of these tools or inputs exists in this checkout.
3. **Label every score.** Numeric results must be labeled either **HOLDOUT-DTI** with evaluator version, number of withheld positives, and 95% CI, or **ORGANIZER-CONFIRMED** copied from a submission receipt. A projection is not a score. Values copied from sibling sites without a receipt remain unverified owner/site claims.
4. **Leakage canary.** Test each feature alone on the holdout; AUC above 0.90 is presumed leakage until investigated.
5. **Run card.** End each experiment with JSON containing hypothesis, mechanism, a named non-fault mimic, holdout result and CI, correlation/overlap with registry, raster SHA-256, validator output (footprint NaNs, range, CRS/shape/transform), submission name/note, and promote/negative verdict.
6. **Budget and slot control.** Stop after three experiments or two hours. Do not choose or spend a competition submission slot in the research step; the selector is separate and must respect any current portal upload cap. The DOE rules describe a single competition entry, so confirm the current final-entry process in the official rules and portal rather than treating repeated uploads as multiple final entries.
7. **Submission artifact safety.** A button may say “Download submission” only when it points to a tested artifact and the page prominently says it is eligible to submit. Otherwise show a clear blocked/not-ready status. Never package an arbitrary all-zero raster, another team's raster, or a projection as a candidate.

## What GEMSDOE32 does and does not establish

The linked [GEMSDOE32 page](https://buffedlizard55-lab.github.io/GEMSDOE32/docs/index.html) describes the H33-2-B2 artifact and a proposed thinning mechanism. It also explicitly says **“NO ORGANISER SCORE EXISTS”** for its artifact and calls its reported projection a model, not a score. Its reported holdout is against visible/catalogued faults and the page warns that such a proxy cannot reward genuinely new faults. Its Monte Carlo comparisons use an owner-report-derived truth-model prior; they are not organizer evaluation receipts. Accordingly, the supplied `0.2778` is **not ORGANIZER-CONFIRMED and is not a HOLDOUT-DTI measurement from this project**; it cannot be attributed to this GeoTIFF as an organizer-confirmed result from the linked page.

A plausible *mechanistic* explanation for why sparse/thinned maps can outperform dense maps under a distance-weighted Tversky objective is that reducing low-credit predicted mass can lower the false-positive penalty while retaining useful spatial coverage. That is a hypothesis about metric behavior, not proof that this artifact achieved a score or that it will improve the private test score. The page's `zeros`/`nan` variants are file-encoding variants; changing outside-footprint fill is not a scientific discovery method. The linked page also reports different values for local proxy/Monte Carlo analyses, which must not be conflated with organizer-confirmed leaderboard scores.

| 2 | **Scale-space magnetic–gravity edge concordance**, using provided TMI/RTP magnetic and isostatic-gravity layers plus provided horizontal/vertical slopes. | Look for boundaries independently supported across potential-field sources, and persistence across scales, rather than a single sharp gradient. Persistence across scales and an independent geophysical support criterion distinguish it from using strain magnitude alone. | **Lower/uncertain potential; low/medium cost.** Coarse strain data may not resolve individual faults. | Smooth regional tectonic gradients and gridding/interpolation artifacts.
