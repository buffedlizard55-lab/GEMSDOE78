How a submission is made — step by step (no manual inspection needed)

  1. Generate: Run bash scripts/restore_data.sh and python scripts/prepare_data.py (GPU helps, CPU also works per reference solution). Then python scripts/build_production_lidar.py --holdout evidence/h79_lidar_holdout_seed20.json (or the corresponding holdout for your lane). The writer vendor/gems57/submission_writer.py validates in memory, writes to temp, validates on-disk, and atomically commits only on pass (fail-closed).
  2. Validate automatically: python scripts/verify_tif.py docs/downloads/<yourfile>.tif checks 12 conditions: single band, float32, EPSG:32611, 3730×3292, transform, no nodata tag, all finite, no NaN inside footprint, values in [0,1], binary 0/1, zero outside footprint, zero on catalogue, and zip single-TIFF byte-identical. Exit 0 = pass; non-zero = do not upload.
  3. Check holdout & uniqueness: Every number must be labeled HOLDOUT-DTI (evaluator version, withheld positives, 95% CI) or ORGANIZER-CONFIRMED (submission-page receipt). Projections are never scores. Uniqueness: Spearman |ρ| ≤0.90 and forward 3-px dot overlap ≤0.70 vs every registry raster, checked on score surface before placement and on final dots. This session's H79 files fail the overlap gate (0.835 and 0.789 >0.70).
  4. Name & note: The writer creates a 140-char-max submission name like gems78-h79ls-lidar-50000dots-20261022T012852Z-e8b05f45-zeros and note like H79-LS lidar+steered HGB B3 50000dots >=2.8px flank3px; HOLDOUT-DTI 0.1898 s20 n=11321. Copy them verbatim into the portal's “Submission name” and “Note” fields (≤140 chars). Do not rename a blocked file and re-upload.
  5. Upload: On DrivenData → New submission → File to submit → choose the .tif or .zip → paste name/note → Create. The portal returns a score; that score is the only ORGANIZER-CONFIRMED value.
  6. Record: Save the portal receipt (screenshot + score) into registry/live_scores.csv as ORGANIZER-CONFIRMED. Without that, the holdout number is not a projection of live score.

All checks are automatic; no human inspector is needed before upload — the validator, holdout, and uniqueness scripts are the inspection.
