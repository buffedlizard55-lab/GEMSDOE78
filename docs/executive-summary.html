Executive summary — exactly how a submission is made

  1. Read the red banner on the home page. If it says OK TO SUBMIT: NO, do not upload that file. It currently says NO for every file in this repo.
  2. Download only from the banner buttons (this session's inspection file: gems78-h78step-flankstep-44090dots-20261022T013740Z-5e78c1c6-DO-NOT-SUBMIT.tif, sha256 5ce829b026be18a07c0c36d7ec103895da8b3b0443966f01f0d5c8a5bbea9c4b; unique name and ≤140-char note are in the banner card). Never rename an old file and call it new.
  3. When a future file's banner says YES: check the weekly cap on the DrivenData submission page first (login-gated; the agent cannot see it and never uploads). Slot choice is a separate selector decision.
  4. DrivenData competition 306 → New submission → choose the single-band GeoTIFF (or a .zip containing only that TIFF) → paste the note from the banner → submit. The portal checks CRS EPSG:32611, shape 3730×3292, the sample geotransform, and values in [0, 1]. This repo's writer emits all-finite float32 values exactly 0/1 with nodata unset and refuses to write otherwise, and the written file is re-read and re-validated automatically (scripts/verify_tif.py) — no human inspector is in the loop, and the "Predicted values must be in range [0, 1]" error cannot occur.
  5. Save the organizer's score receipt next to the file's SHA-256 and record it as ORGANIZER-CONFIRMED. Until that receipt exists, there is no live score — there are only HOLDOUT-DTI numbers and owner reports.

Rules and sources for manual review: competition home · problem + metric · leaderboard · rules PDF · official reference solution. Non-GitHub hosts were unreachable from this session's sandbox; nothing on this page depends on having fetched them.
